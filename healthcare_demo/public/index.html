📌 Reflected XSS – How It Works

The server reflects user input back into the HTML response without sanitization. An attacker crafts a malicious URL containing a script payload and tricks a patient into clicking it. The browser executes the injected script in the context of the healthcare portal.
⚠️ Vulnerable Search
Input injected directly into HTML – no encoding
💡 Try this XSS payload in the search box: <img src=x onerror=alert('XSS Attack! Cookies: '+document.cookie)> 
// ❌ VULNERABLE server code
app.get('/vulnerable/search', (req, res) => {
  const query = req.query.q;
  // User input injected directly — NO encoding
  res.send(`<h2>Results for: ${query}</h2>`);
});
✅ Secure Search
Input validated + HTML-encoded with he.encode()
💡 Try the same XSS payload here — it will be neutralized: <img src=x onerror=alert('XSS Attack! Cookies: '+document.cookie)> 
// ✅ SECURE server code
const he = require('he');

app.get('/secure/search', (req, res) => {
  const query = req.query.q || '';
  // Strip non-alphanumeric chars
  const sanitized = query
    .replace(/[^a-zA-Z0-9\s\-\.]/g, '');
  // HTML-encode before rendering
  const encoded = he.encode(sanitized);
  res.send(`<h2>Results for: ${encoded}</h2>`);
});

📌 Stored XSS – How It Works

The attacker submits a malicious script through a form (e.g. patient message). The server stores it without sanitization. Every user who loads the page triggers the script — no crafted link required. This is the most dangerous form of XSS.
⚠️ Vulnerable Message Board
Messages stored and rendered without sanitization
💡 Submit this payload as a message: <img src=x onerror=alert('Stored XSS! Your session: '+document.cookie)> 
// ❌ VULNERABLE – stored without sanitization
app.post('/vulnerable/messages', (req, res) => {
  const { content } = req.body;
  messages.push({ content }); // raw push
});

// ❌ VULNERABLE – rendered without encoding
messages.forEach(msg => {
  html += `<p>${msg.content}</p>`;
});
✅ Secure Message Board
Sanitized with DOMPurify + encoded with he.encode()
💡 Submit the same payload here — it will be stripped completely: <img src=x onerror=alert('Stored XSS! Your session: '+document.cookie)> 
// ✅ SECURE – DOMPurify sanitization on store
const DOMPurify = createDOMPurify(new JSDOM('').window);

app.post('/secure/messages', (req, res) => {
  const safe = DOMPurify.sanitize(
    req.body.content, { ALLOWED_TAGS: [] }
  );
  messages.push({ content: safe });
});

// ✅ SECURE – he.encode() on render
messages.forEach(msg => {
  html += `<p>${he.encode(msg.content)}</p>`;
});

📌 DOM-Based XSS – How It Works

The attack payload is processed entirely in the browser via JavaScript DOM manipulation. No data is sent to or reflected by the server — making it invisible to server-side defenses. This demo runs entirely client-side.
⚠️ Vulnerable DOM Rendering
Uses innerHTML with URL parameter — no sanitization
💡 Click "Inject Payload" to simulate the attack URL: ?name=<img src=x onerror=alert('DOM XSS!')>

Rendered Output (Vulnerable):

Welcome, Patient!
// ❌ VULNERABLE – innerHTML with URL param
const params = new URLSearchParams(
  window.location.search
);
const name = params.get('name');

// innerHTML interprets HTML tags!
document.getElementById('banner')
  .innerHTML = 'Welcome, ' + name;
✅ Secure DOM Rendering
Uses textContent — never interprets HTML tags
💡 Same payload is neutralized — rendered as plain text: ?name=<img src=x onerror=alert('DOM XSS!')>

Rendered Output (Secure):

Welcome, Patient!
// ✅ SECURE – textContent + validation
const raw = params.get('name') || '';

// Strip non-letter chars, limit length
const safe = raw
  .replace(/[^a-zA-Z\s\-]/g, '')
  .slice(0, 100);

// textContent NEVER renders HTML!
document.getElementById('banner')
  .textContent = 'Welcome, ' + safe;

📌 eval() Vulnerability – How It Works

eval() executes any JavaScript string as code at runtime. If user input reaches eval(), an attacker can inject arbitrary logic — from data exfiltration to privilege escalation. The server-side demo shows a patient record filter powered by eval().
⚠️ Vulnerable Filter (eval)
User expression passed directly to eval()
💡 Try these inputs: Normal: record.age > 40
Attack: record.age > 0; console.log('INJECTED:', JSON.stringify(patientRecords)) 
// ❌ VULNERABLE – eval() on user input
app.post('/vulnerable/filter', (req, res) => {
  const { expression } = req.body;

  // eval() executes ANY string as JS code!
  const filterFn = eval(
    `(record) => ` + expression
  );
  const results = records.filter(filterFn);
  res.json({ results });
});
✅ Secure Filter (Whitelist)
Only predefined filter keys accepted — no eval()
💡 Only these keys are allowed (no custom code): age_over_40 | age_over_60 | all_records 
// ✅ SECURE – Whitelist-based, no eval()
const ALLOWED = {
  'age_over_40': r => r.age > 40,
  'age_over_60': r => r.age > 60,
  'all_records': r => true,
};

app.post('/secure/filter', (req, res) => {
  const { filterKey } = req.body;
  if (!ALLOWED.hasOwnProperty(filterKey))
    return res.json({ error: 'Invalid key' });

  const results = records.filter(ALLOWED[filterKey]);
  res.json({ results });
});
